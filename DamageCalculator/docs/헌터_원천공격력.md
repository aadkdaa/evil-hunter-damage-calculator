# 헌터 원천 공격력

## 목적

APK에 저장된 헌터 원천 공격력 데이터와 생성 방식을 정리한다.

여기서 `원천 공격력`은 헌터 상세창에 표시되는 최종 공격력이 아니다. 장비, 레벨, 환생, 공격력 증가 옵션 등을 적용하기 전 헌터 객체에 저장되는 기본 공격력 값이다.

## 분석 범위

- 대상 APK: v1.373, v1.376
- 확인일: 2026-09-03
- 분석 방식: APK 파일과 추출 에셋 및 복호화된 IL2CPP 코드의 정적 분석
- 실행 중인 앱, LD플레이어, 프로세스 메모리 및 보안 모듈은 사용하지 않음

## 결론

헌터 원천 공격력은 세부 전직 45종마다 따로 정해지는 값이 아니다. 헌터의 `기본 직업 번호`로 5개 직업 계열 중 하나를 선택하고, 해당 계열의 공격력 범위에서 정수 난수를 뽑아 저장한다.

- 기본 직업 번호만 원천 공격력 표 선택에 사용한다.
- 2차 및 3차 전직 값은 별도 필드에 저장되며 원천 공격력 표 선택에는 사용되지 않는다.
- 생성된 원천 공격력은 헌터 데이터에 저장된다.
- 저장 데이터에서 헌터를 다시 만들 때는 기존 원천 공격력을 그대로 복사한다.
- 상세창을 열거나 전직할 때 원천 공격력을 다시 추첨하는 구조가 아니다.

### APK 기준 최종 범위

APK 객체에 실제로 저장되는 원천 공격력의 결론은 다음과 같다.

| 기본 직업 계열 | APK 원천 공격력 범위 |
| --- | ---: |
| 버서커·팔라딘·다크나이트 | **90~100** |
| 레인져·소서러 | **100~110** |
| 전체 직업 통합 | **90~110** |

최솟값과 최댓값을 모두 포함하는 정수 범위다.

현재 계산기의 `고유공격력`은 APK 원천 공격력 자체가 아니라 환생·레벨 보정을 적용한 뒤 계산기 식의 앞쪽 `2`에 맞춰 절반으로 환산한 값이다.

```text
계산기 고유공격력
= APK 원천공격력 × 환생계수 × 레벨계수 ÷ 2
```

최대 환생 5회와 레벨 100을 전제로 하면 환생계수는 15, 레벨계수는 1.30이다.

| 기본 직업 계열 | 계산기 고유공격력 범위 |
| --- | ---: |
| 버서커·팔라딘·다크나이트 | **877.5~975** |
| 레인져·소서러 | **975~1,072.5** |
| 전체 직업 통합 | **877.5~1,072.5** |

따라서 계산기의 임시 범위 `800~1,200`은 실제 범위를 포함하는 넓은 탐색 범위이며, APK 기준으로 좁힌 정확한 전체 범위는 `877.5~1,072.5`다.

## APK 원본 공격력 표

APK의 `Hunter` 데이터에는 각 기본 직업 계열마다 공격력 범위 세 개가 중첩 배열로 들어 있다.

| 기본 직업 번호 | 기본 직업 계열 | damage[0] | damage[1] | damage[2] |
| ---: | --- | ---: | ---: | ---: |
| 0 | 버서커 계열 | 80~90 | 90~100 | 100~110 |
| 1 | 팔라딘 계열 | 80~90 | 90~100 | 100~110 |
| 2 | 레인져 계열 | 90~100 | 100~110 | 110~120 |
| 3 | 소서러 계열 | 90~100 | 100~110 | 110~120 |
| 4 | 다크나이트 계열 | 80~90 | 90~100 | 100~110 |

`damage`는 APK 내부의 중첩 배열이다. `[0]`, `[1]`, `[2]`는 그 배열 안의 세 범위를 뜻한다. 각 범위가 게임 화면에서 어떤 등급명에 해당하는지는 이번 정적 분석만으로 확정하지 않는다.

## 실제 생성 코드에서 사용하는 범위

v1.376에서 원천 공격력을 헌터 데이터에 기록하는 두 생성 경로는 모두 다음 방식으로 계산한다.

```csharp
int jobIndex = hunter.job;
HunterBaseStat row = hunterStatTable[jobIndex];

int minimum = row.damage[1][0];
int maximum = row.damage[1][1];

// 정수형 Random.Range는 두 번째 인자를 포함하지 않으므로 +1을 한다.
hunter.damage = Random.Range(minimum, maximum + 1);
```

따라서 실제 생성 범위는 다음과 같다.

| 기본 직업 번호 | 기본 직업 계열 | 원천 공격력 생성 범위 | 가능한 최댓값 |
| ---: | --- | ---: | ---: |
| 0 | 버서커 계열 | 90~100 | 100 |
| 1 | 팔라딘 계열 | 90~100 | 100 |
| 2 | 레인져 계열 | 100~110 | 110 |
| 3 | 소서러 계열 | 100~110 | 110 |
| 4 | 다크나이트 계열 | 90~100 | 100 |

최솟값과 최댓값을 모두 포함하는 정수 범위다. 레인져와 소서러 계열은 나머지 세 계열보다 원천 공격력이 10 높은 범위를 사용한다. 세 번째 범위인 `damage[2]`는 확인한 두 생성 경로에서 원천 공격력 생성에 사용되지 않는다.

## 데이터 형태 요약

다음은 APK의 `Hunter` 에셋 내용을 분석용으로 단순화한 형태다.

```text
job 0: damage=[[80,90], [90,100], [100,110]]
job 1: damage=[[80,90], [90,100], [100,110]]
job 2: damage=[[90,100], [100,110], [110,120]]
job 3: damage=[[90,100], [100,110], [110,120]]
job 4: damage=[[80,90], [90,100], [100,110]]
```

같은 데이터 행에는 체력, 방어력, 회피, 치명타 범위도 함께 들어 있다. 이번 문서에서는 원천 공격력만 다룬다.

## 상세창 공격력과의 관계

헌터 원천 공격력은 상세창 공격력 계산의 출발값 중 하나다.

```text
기본 공격력 덩어리
= 장비 고정 공격력
  + 원천 공격력 × 무기 계수 × 환생 계수 × 레벨 계수
```

그 뒤 다음 보정이 추가된다.

- 개인 공격력 증가
- 장비 옵션의 전체 공격력 증가
- 헌터 등급 공격력 증가
- 장비 강화, 건물, 펫 및 길드 공격력
- 코스튬, 인장, 수집, 탑승펫 및 유물 공격력
- 일부 특수 헌터 배율
- 직업 특성, 버프 및 공격력 포션
- 상세창 전용 직업 및 장비 특수 보정

따라서 `원천 공격력 120`은 상세창에 120으로 표시된다는 뜻이 아니다. 이후의 레벨·환생·장비·퍼센트 배율로 크게 증폭된다.

헌터의 `공격력 등급 증가`도 원천 공격력에 합쳐 저장되는 값이 아니다. 최종 공격력 계산의 일반 퍼센트 공격력 그룹에 별도로 들어간다.

## 분석 재개용 코드 위치

아래 주소는 v1.376의 복호화된 ARM64 `libil2cpp` 기준이다.

| 내용 | 위치 또는 오프셋 |
| --- | --- |
| `HunterData.job` | 객체 `+0x20` |
| `HunterData.subJob` | 객체 `+0x30` |
| `HunterData.thirdJob` | 객체 `+0x40` |
| `HunterData.damage` | 객체 `+0x200` |
| 원천 공격력 getter | `0x2364F38` |
| 원천 공격력 setter | `0x2364F44` |
| 헌터 복사 시 원천 공격력 복사 | `0x2365F30`~`0x2365F34` |
| 저장·전송용 데이터에서 원천 공격력 복사 | `0x238DB2C`~`0x238DB34` |
| 생성 경로 1의 원천 공격력 기록 | `0x25869E4`~`0x2586A40` |
| 생성 경로 2의 원천 공격력 기록 | `0x258EFF0`~`0x258F0C0` |
| 직업별 능력치 표 접근 | 반환 객체의 `+0x60`, `job`으로 인덱싱 |
| 정수 난수 함수 | `0x4AC0BC4` |

생성 경로 두 곳 모두 `damage[1][0]`을 최솟값으로, `damage[1][1] + 1`을 정수 난수 함수의 제외 상한으로 전달한다. 즉 두 번째 범위 하나만 사용한다.

## 검증 근거

1. v1.376의 생성 코드에서 원천 공격력 기록 지점 두 곳을 각각 확인했으며 두 곳 모두 같은 범위 선택 및 난수 계산을 사용한다.
2. APK 에셋의 `Hunter` 데이터에서 직업 번호, 전직 명칭 및 세 공격력 범위를 직접 추출했다.
3. v1.373과 v1.376의 `Hunter` 에셋을 별도로 추출해 비교했으며 직업 구성과 모든 공격력 범위가 동일했다.
4. 헌터 복사 및 저장 데이터 변환 경로에서 이미 저장된 원천 공격력을 그대로 복사하는 것을 확인했다.

## 아직 확정되지 않은 부분

- `damage[0]`, `damage[1]`, `damage[2]` 세 범위가 게임 UI에서 각각 어떤 등급명 또는 생성 조건으로 불리는지는 미확정이다.
- 기존 헌터 한 명의 정확한 원천 공격력은 해당 헌터에게 저장된 값을 직접 확보하거나, 나머지 공격력 계수와 옵션을 모두 알고 역산해야 한다.
