# 체력 계산공식

## 적용 범위

- 헌터 상세 정보에 저장되는 최대 체력 계산식이다.
- 대상 APK: v1.373, v1.376
- 실행 중인 앱이나 LD플레이어는 사용하지 않고 복호화된 IL2CPP 코드와 APK 에셋만 정적 분석했다.
- 아래 식은 v1.376을 기준으로 한다. v1.373은 유물 체력 항목만 없고 계산 구조와 버림 순서가 같다.

## 원천 체력

헌터 생성 코드는 기본 직업 번호로 `Hunter` 데이터 행을 고른 뒤, 체력 범위 배열의 두 번째 범위에서 정수 난수를 뽑는다. 최솟값과 최댓값을 모두 포함한다.

| 기본 직업 번호 | 직업 계열 | APK에 저장된 세 범위 | 실제 생성 범위 |
| ---: | --- | --- | ---: |
| 0 | 버서커 | 6,000~6,200 / 6,200~6,400 / 6,400~6,600 | 6,200~6,400 |
| 1 | 팔라딘 | 6,000~6,200 / 6,200~6,400 / 6,400~6,600 | 6,200~6,400 |
| 2 | 레인져 | 5,600~5,800 / 5,800~6,000 / 6,000~6,200 | 5,800~6,000 |
| 3 | 소서러 | 5,600~5,800 / 5,800~6,000 / 6,000~6,200 | 5,800~6,000 |
| 4 | 다크나이트 | 6,000~6,200 / 6,200~6,400 / 6,400~6,600 | 6,200~6,400 |

```text
원천체력 = Random.Range(두 번째 범위 최솟값, 두 번째 범위 최댓값 + 1)
```

## 환생·레벨 계수

```text
환생계수 R = 환생 횟수가 0이면 1
             환생 횟수가 1 이상이면 환생 횟수 × 3

레벨계수 L = 1 + 레벨 × 0.003
```

예를 들어 레벨 100의 레벨계수는 `1.30`이다.

## 기본 체력 덩어리

```text
기본체력 = 장비 고정체력 + 원천체력 × R × L
```

장비 고정체력은 현재 착용 장비에서 집계된 고정 체력 합계다.

## 일반 체력 합

아래 값은 `7 = 7%`와 같은 퍼센트 포인트 단위로 합산된다.

```text
일반체력합 P
= 개인 체력
 + 장비 옵션 체력
 + 헌터 등급 체력
 + 건물 체력
 + 마을 펫 체력 항목 1
 + 마을 펫 체력 항목 2
 + 길드 체력
 + 비법/GUP 체력
 + 바이탈리티 체력
 + 요정 체력
 + 럼블펫 체력
```

## 직접 비율 체력 합

아래 값은 `0.07 = 7%`와 같은 소수 비율로 저장되어 그대로 더해진다.

```text
직접체력합 Q
= 장비 체력 강화
 + 코스튬 체력
 + 도감 체력
 + 영웅 직업 특성 체력
 + 라이딩펫 체력
 + 유물 체력
```

따라서 체력 퍼센트 덩어리는 다음과 같다.

```text
체력비율 = 1 + P ÷ 100 + Q
```

`P`와 `Q`는 서로 곱하지 않는다. 단위를 맞춘 뒤 하나의 덧셈 그룹이 된다.

## 길드 추가 체력 배율

길드 객체에 저장된 별도 체력 비율은 위 합산 그룹에 넣지 않고 마지막에 곱한다.

```text
길드추가배율 G = 1 + 길드 추가 체력 비율
```

## 최종 공식과 버림 순서

```text
계산체력
= trunc(
    기본체력
  × 체력비율
  × G
)

최종체력 = max(1, 계산체력)
```

`trunc`는 소수점 이하를 0 방향으로 버리는 정수 변환이다. 계산 결과가 0 이하이면 최종 체력을 1로 제한한다.

새 최대 체력이 현재 체력보다 커지면 현재 체력도 새 최대 체력까지 올려서 저장한다. 최대 체력이 낮아졌을 때는 이 분기에서 현재 체력을 강제로 낮추지 않는다.

## 계산기용 한 줄 공식

```text
최종체력
= max(
    1,
    trunc(
      (장비 고정체력 + 원천체력 × R × L)
      × (1 + 일반체력합 ÷ 100 + 직접체력합)
      × (1 + 길드 추가 체력 비율)
    )
  )
```

## 검증

1. v1.376 최종 체력 함수의 산술 명령, 필드 접근, 정수 변환 및 최소값 제한 순서를 직접 복원했다.
2. v1.373의 대응 함수에서 같은 계산 구조와 버림 순서를 다시 확인했다.
3. v1.376의 헌터 생성 경로 두 곳에서 같은 원천 체력 범위 선택과 난수 저장 방식을 확인했다.
4. v1.373과 v1.376의 `Hunter` 에셋 체력 데이터가 동일함을 확인했다.
