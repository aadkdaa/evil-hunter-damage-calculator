# 개발 규칙

## 프로젝트 구조와 실행

- 계산기는 별도 프레임워크나 빌드 과정이 없는 정적 웹 앱입니다.
- 주요 실행 파일은 `index.html`, `styles.css`, `app.js`입니다.
- 모든 계산은 서버가 아니라 사용자의 브라우저에서 실행합니다.
- 로컬 개발 주소는 `http://127.0.0.1:8765/`입니다.
- 로컬 주소에서는 개발 편의를 위해 접속 코드 화면을 자동으로 건너뜁니다.
- 외부에서 나타나는 클라이언트 측 접속 코드는 강한 보안 기능으로 간주하지 않습니다.

## 화면 구현 기준

- `기본세팅`과 `데미지 계산 2` 탭을 입력 순서, 간격, 크기, 좌우 배치, 폴딩 방식과 문구의 기준으로 사용합니다.
- 최종 사용자 흐름은 `정보 입력 → 공격력 계산 → 데미지 계산 → 장비 비교` 순서로 구성합니다.
- `저장 / 로드`는 계산 단계가 아니라 보조 기능으로 취급합니다.
- 기존 `데미지 계산`은 `계산기_1.xlsx`를 웹으로 옮긴 참고·검산용 구현입니다. 최종 UI 기준으로 사용하지 않으며 새 공식 구현이 완료될 때까지 보존합니다.
- `데미지 계산 2`는 사용자가 원하는 최종 UX의 화면 틀입니다. 현재 들어 있는 계산식과 결과는 사용자가 요청하거나 확정한 공식으로 간주하지 않습니다.
- 기존 엑셀 구현 영역을 수정할 때는 수식과 데이터 의미를 보존하되, 별도 요청이 있으면 기준 화면의 패턴으로 재구성합니다.
- 스탯의 기본 표시 순서는 `공격력 → 방어력 → 체력 → 이동속도`입니다.
- 해당 스탯이 없는 영역은 존재하는 항목만 기본 순서에 맞춰 배치합니다.
- 기본 스탯 뒤에는 `치명타 피해 → 보스 피해 → 영장 피해 → 종족 피해 → 받는 피해 감소` 등 해당 영역의 나머지 항목을 배치합니다.
- 수치 입력칸과 라벨은 `기본세팅`의 크기, 간격, 왼쪽 정렬 방식을 기준으로 합니다.
- `%`는 라벨에 반복해서 붙이지 않고 필요한 경우 입력칸 내부의 단위 표시로 사용합니다.
- `기본세팅`의 사용 너비는 `데미지 계산 2` 왼쪽 입력 영역과 맞춥니다.
- 폴딩 입력 영역은 여러 개를 동시에 펼쳐둘 수 있게 합니다. 하나를 열 때 다른 영역을 자동으로 접지 않습니다.
- `데미지 계산 2`는 왼쪽에 폴딩 가능한 입력 영역, 오른쪽에 충분히 넓은 계산 결과 영역을 둡니다.
- 사용자가 이미 이해하고 있는 내용을 반복하는 상세 안내나 “계산하세요” 같은 문구를 추가하지 않습니다.

## 공식과 계산 구현

- 공식과 검산 근거는 저장소 안의 `DamageCalculator` 문서를 기준으로 합니다.
- 새 공격력 공식은 사용자가 정리한 공식과 분류 문서를 기준으로 하고, 기존 엑셀 공식은 참고·검산 기준으로 사용합니다.
- 화면에 임시로 연결된 계산식은 확정 공식과 분리하며, 사용자 확인 없이 최종 공식으로 승격하지 않습니다.
- 구현 순서는 공격력 계산, 초당공격력, 평타·종족별 데미지, 증폭 버프, 세팅 비교 순입니다.
- 방어력과 체력은 원천값 처리 방식이 확정될 때까지 정식 계산 결과 구현을 보류합니다.
- 확정 공식은 계산 결과에 사용하고, 미확정 값은 가설·직접 입력값·검산값으로 명확히 분리합니다.
- 이미 구현된 공식을 다시 만들지 말고 기존 코드와 검산 자료를 확인한 뒤 이어서 구현합니다.

## 상태 저장

- 입력값은 브라우저 `localStorage`에 자동 저장하며 저장/로드 백업에도 포함합니다.
- 저장 구조를 변경할 때는 기존 저장 데이터를 가능한 한 유지하거나 변환합니다.
- 탭을 삭제하거나 숨길 때는 과거에 저장된 활성 탭 때문에 빈 화면이나 숨긴 화면이 열리지 않도록 처리합니다.

## 변경과 배포

- 요청과 관계없는 사용자 파일이나 기존 변경을 수정·삭제하지 않습니다.
- 작업 후 JavaScript 구문 검사, 변경 파일 검사와 로컬 페이지 응답을 확인합니다.
- GitHub Pages는 사용자가 명시적으로 요청할 때만 게시합니다.
